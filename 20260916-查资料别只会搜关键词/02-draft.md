# 第 4 篇笔记｜V1 初稿与配图方案

状态：执行编辑 A 初稿，待策划评审 B 审核；不是最终发布稿。

## 1. 执行定位

- 目标读者：要为学习、工作或内容创作查陌生主题，但不熟悉核对来源的 AI 新手。
- 读者此刻的问题：AI 很快给了答案，却不知道它依据什么、是否适用于自己的情况。
- 本篇交付：可照做的 3 步顺序——AI 找线索 → 打开原文核实 → 按用途整理。
- 贯穿案例：一位 Windows 11 用户要把“如何截取局部屏幕、截图存在哪里”写成给同事看的简短说明。案例为公开、非敏感场景；微软原文已核对，AI 搜索界面与生成结果尚未实测。
- 真实性边界：第 3～4 页的搜索框、引用入口是排版示意，不是 Perplexity 实际查询截图；第 6 页只给整理指令，不冒充 ChatGPT 实际回复。

## 2. 候选标题与选择

1. **查资料别只会搜关键词：这 3 步更省事**（推荐）。有具体痛点和明确动作，承接策划方向；“更省事”表达流程更顺手，不作速度或准确率承诺。
2. AI 给了答案，为什么还要点开来源？（备选）。反常识问题有点击潜力，但标题没有直接点出第 3 步“整理”。
3. 用 AI 查资料，先做这 3 步再引用（备选）。行动明确，但“引用”稍偏学生／内容作者，覆盖面较窄。

不使用“我一直这样查”等未经实际使用验证的第一人称经验话术。最终标题由 B 评审确认。

## 3. 封面信息结构

- 品牌条：效率研究所｜第 4 篇（小字；仅在前三篇已发布的前提下保留）。
- 主标题：**查资料，先走这 3 步**。
- 副信息：**找线索 → 核原文 → 再整理**。
- 视觉焦点：一个大号“3”和三段简短箭头路径；不放产品标志，不塞完整提问和免责说明。
- 缩略图优先级：先看到“查资料”和“3 步”，其次才看清步骤小字。

## 4. 发布正文｜V1

AI 查资料很方便，但它给出答案，不等于这段话已经能放心转给别人。

比如想给同事说明“Windows 11 怎么截取局部屏幕，截图会存在哪里”，可以按这 3 步走：

① 先用 AI 搜索找线索：问清楚问题，顺手要出处。Perplexity 是一种选择，重点不是换工具，而是找到能打开的来源。

② 点开原文核实：看页面是谁发布的、适用哪个版本、原文到底怎么说。这个例子我核对的是微软的《使用截图工具捕获截图》：页面适用于 Windows 11 和 Windows 10；在 Windows 11 的说明中，Windows 键 + Shift + S 可打开截图工具，截图默认自动保存到“屏幕截图”文件夹，保存行为也能在设置里更改。页面未标注发布日期，本稿于 2026-09-16 核对。

③ 最后再整理：把核对过的信息交给 AI，说明“给谁看、用来做什么、要多短”，并让它把不确定的地方标出来。发给别人前，自己再读一遍来源与结果。

记住这个顺序：**先找线索，再核原文，最后整理。**有引用，也不代表引用一定对、内容一定新。

你最常查哪类资料：软件操作、学习知识，还是工作资料？

#AI工具 #查资料 #Perplexity #ChatGPT #电脑效率 #办公效率 #效率工具

发布前须根据 B 的评审再校对平台字数、标签与当天来源状态；本段目前不是最终发布稿。
